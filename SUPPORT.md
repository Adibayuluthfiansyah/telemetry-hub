# Support

Telemetry Hub is a pre-release, maintainer-run project. The community is small
and the maintainer is one person — responses are best-effort, and good reports
get faster answers. Here is where each kind of help belongs.

## Questions

**GitHub Discussions** (if enabled on this repository) is the right place for
"how do I…" questions, design discussion, and ideas that are not yet concrete
enough to be issues.

If Discussions is not enabled, open a regular issue with the question — it
will be labeled and closed when answered.

Before asking, check:

- [README.md](README.md) — quick start and configuration
- [CONTRIBUTING.md](CONTRIBUTING.md) — workspace and development setup
- [docs/](docs/) — product vision and architecture

## Bug reports

Open a bug report using the
[bug report template](.github/ISSUE_TEMPLATE/bug_report.yml). A good report
includes the exact command, the Rust/PostgreSQL versions, and the full error
output. Reproducible reports beat long descriptions.

## Feature requests

Open a feature request using the
[feature request template](.github/ISSUE_TEMPLATE/feature_request.yml).
The template asks where the feature belongs in the architecture — the
answer is what makes a request actionable. If a feature needs a new flag or
mode to coexist with the architecture, it will likely be redesigned; see
`docs/PRODUCT_VISION.md`.

## Security reports

**Do not open public issues for security problems.** Report privately per
[SECURITY.md](SECURITY.md) — email
adibayuluthfiansyah@gmail.com with a `[SECURITY]` subject, or use the GitHub
Security tab. This is the one support path with a guaranteed response
timeline.

## Expectations

- Bug reports and feature requests get triaged within a few days.
- There is no SLA on fixes — this is a learning-oriented project with one
  maintainer.
- Contributions that follow [CONTRIBUTING.md](CONTRIBUTING.md) get priority
  over feature wishes; the project ships by accretion of disciplined PRs.
